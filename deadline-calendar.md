# Deadline Calendar — Government Deadline & Notification Hub

Documentation for the feature added on 2026-08-20. Covers architecture, how
to add/update a deadline from the admin panel, and troubleshooting.

## What changed

| File | What it does |
|---|---|
| `supabase/deadlines-schema.sql` | New `deadlines` table + RLS policies. Run once in Supabase SQL Editor. |
| `admin/deadlines.html` | Admin page — add/edit/publish/delete deadlines. Bulk JSON import included. |
| `tools/deadline-calendar.html` | Public listing page — hero, summary counters, filters, search, list view, calendar view. |
| `assets/js/deadline-calendar.js` | Listing page logic (fetch, filter, search, status calculation, calendar render). |
| `assets/css/deadline-calendar.css` | Styles for the listing page (scoped to `.dl-` classes, won't clash with existing CSS). |
| `tools/deadline-detail.html` | Template for one deadline's own SEO page, reached via `?slug=...`. |
| `assets/js/deadline-detail.js` | Detail page logic: meta tags, JSON-LD (WebPage/BreadcrumbList/FAQPage/Event), body sections, related deadlines. |
| `admin/dashboard.html`, `jobs.html`, `exams.html`, `services.html`, `blog.html`, `csc.html`, `comments.html`, `subscribers.html`, `analytics.html` | Added a "🗓️ Deadlines" link to the sidebar nav (mechanical addition only — nothing else touched). |

Nothing existing was deleted, renamed, or restructured. The old
`tools/deadline-calendar.html` used hard-coded dummy events with no backend;
it's now wired to Supabase like the existing Job Alerts / Exam Calendar
tools already are, so it follows a pattern that's already live and known to
work on this site.

## One-time setup

1. Open Supabase Dashboard → SQL Editor → New query.
2. Paste the contents of `supabase/deadlines-schema.sql` → Run.
3. That's it — no other config needed. `assets/js/supabase-client.js` (already
   in the repo) is reused as-is.

## Adding a deadline (day-to-day use)

1. Go to `/admin/deadlines.html` (log in if asked).
2. Fill in:
   - **Title** (English required, Hindi optional)
   - **SEO Title / SEO Description** (English & Hindi) — you write these
     yourself, so the Google search-result snippet says exactly what you
     want instead of a generic template title.
   - **Category / Deadline Type / State**
   - **Deadline Date** (required) and **Official URL** (required)
   - **Last Verified** — the date you personally checked this against the
     official notification/portal. Fill this in every time you touch the
     record.
   - Optional detail-page sections: Overview, Eligibility, Documents, How to
     Apply, Important Dates, What if missed, FAQ.
3. Click **Publish**. It appears immediately:
   - On `/tools/deadline-calendar.html` (in the matching category/filters)
   - At its own page: `/tools/deadline-detail.html?slug=<auto-generated-slug>`
4. Click **Save draft** instead of Publish if you want to come back and
   double-check the date before it goes live. Drafts are only visible to
   your logged-in admin session (via RLS), and the detail page shows an
   orange "Draft preview" banner so you can't confuse it with a live page.

No code changes or GitHub deploy are needed for any of this — it's a
straight database write from the admin form, same as Job Alerts and Exam
Calendar already work on this site.

### FAQ field format

Plain text, one question/answer pair per block, separated by a blank line:

```
Q: What is the last date?
A: 30 August 2026.

Q: Can it be extended?
A: Only if an official notification confirms it.
```

This gets parsed into a `FAQPage` JSON-LD block automatically. Leave it
blank if you don't have genuinely useful FAQ content yet — an empty/fake
FAQ block should never be published (see Section 32 of the original spec:
"Fake FAQ content mat generate karo").

### Bulk import

On `/admin/deadlines.html`, the "Bulk import" box accepts a JSON array:

```json
[
  {
    "title_en": "PM-Kisan e-KYC Last Date 2026",
    "title_hi": "पीएम-किसान ई-केवाईसी अंतिम तिथि 2026",
    "category": "scheme",
    "deadline_type": "ekyc",
    "state": "all-india",
    "deadline_date": "2026-08-30",
    "official_url": "https://pmkisan.gov.in/",
    "source_name": "Official PM-Kisan Portal"
  }
]
```

`title_en`, `deadline_date`, and `official_url` are required per item;
everything else is optional and can be filled in later via Edit. Check
"Publish immediately" only if every item in the batch is already verified —
otherwise leave it unchecked and publish each one individually after review.

### Marking a deadline as extended

Edit the existing deadline, fill in **Previous Deadline Date** and
**Extension Reason**, then update **Deadline Date** to the new date and
save. The detail page will then show:

> Deadline Updated: 23 August 2026 → 30 August 2026 (Official extension notification)

### Deleting vs. Unpublishing

Prefer **Unpublish** over **Delete** for anything that was ever live and
indexed by Google — it keeps the record (and its URL) intact in case you
want to bring it back, while removing it from public view. **Delete** is
permanent.

### Related Tools & Related Services on the detail page

- **Related Tools** — automatic, no admin work needed. Based on the
  deadline's **Category**, the detail page shows 3 relevant tools from
  `/tools/` as icon cards (e.g. category `tax` → Income Tax Calculator, HRA
  Calculator, Late Filing Penalty Calculator). The mapping lives in
  `assets/js/deadline-detail.js` (`TOOLS_BY_CATEGORY` / `TOOL_META`) — edit
  there if you want to change which tools show for a category.
- **Related Government Services** — optional, admin-entered, since there's
  no reliable way to auto-guess which of the site's 180+ `/service/` pages
  is relevant. On `/admin/deadlines.html`, fill the **Related Government
  Services** box, one per line:
  ```
  pm-kisan|PM-KISAN Scheme|पीएम-किसान योजना
  e-shram-card|e-Shram Card|ई-श्रम कार्ड
  ```
  Format: `slug|English Name|Hindi Name`. The slug must match an existing
  page at `/service/<slug>.html`. Leave this box empty if you're not sure —
  the section simply won't render rather than show a guessed or broken
  link.
- **Related Deadlines** — automatic, same as before: up to 4 other
  published deadlines in the same category, live from the database.

All three now render as the same icon-card style used elsewhere on the
site, not a plain text list.



Closing Today / Ends Tomorrow / X Days Left / Upcoming / Expired are never
stored in the database — `deadline-calendar.js` and `deadline-detail.js`
both compute this live from `deadline_date` vs today's date every time the
page loads. This means:

- You never need to go back and manually mark something "Expired."
- Expired deadlines are **not deleted or hidden** — they move into an
  "Expired / Past Deadlines" section on the listing page and stay reachable
  on their own detail page, so the page keeps its SEO value and search
  ranking instead of becoming a dead link.

## What was intentionally left out of this build (automation)

The original spec included full automation: GitHub Actions scanning
official sources daily, auto-generating new SEO pages, auto-updating the
sitemap, auto-committing to Git. Per your instruction, **that part was
skipped for now** in favor of the manual admin-panel workflow described
above, since you already have Supabase and wanted to publish directly.

If/when you want the automation layer later, the safe path (per the
original spec's own caution) is:
1. A GitHub Actions workflow on a daily schedule.
2. Pulling only from official APIs/RSS feeds — never random blogs as the
   primary source.
3. Writing to a **review/draft queue** in this same `deadlines` table
   (`status = 'draft'`), never auto-publishing.
4. You review and click Publish from `/admin/deadlines.html`, same as now.

This keeps the admin panel as the single source of truth either way — the
automation would just be a faster way to get drafts in front of you instead
of typing them by hand.

## Sitemap / indexing

Individual deadline pages (`deadline-detail.html?slug=...`) are not yet
added to `sitemap.xml` — that file was not touched in this build. If you
want new deadlines to get indexed faster, either:
- Add important slugs to `sitemap.xml` manually as you publish them, or
- Use Google Search Console → URL Inspection → Request Indexing for
  high-priority ones (e.g. something with a lot of expected search volume).

## Troubleshooting

- **"Backend not configured" on admin page** → `assets/js/supabase-client.js`
  couldn't get a client; check the Supabase URL/key config it already uses
  for Jobs/Exams (unchanged by this build).
- **New deadline not showing on the calendar page** → confirm status is
  "Published" (not "Draft") in the admin table.
- **Detail page says "Deadline not found"** → the slug in the URL doesn't
  match any published (or, if you're logged in, draft) row — check for a
  copy-paste typo in the link.
- **Badge shows the wrong "days left"** → this is computed from the
  browser's local date; if a user's device clock is wrong, the badge will
  be off for them specifically — this isn't fixable from the data side.
