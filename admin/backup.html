Safe manual backup checklist

  1. Confirm you are in the correct Supabase project before exporting anything.
  2. Review the plan's backup/PITR availability and retention period in Supabase.
  3. Export only the required database data/schema using the provider's documented process.
  4. Store the backup in an access-controlled location outside the public repository.
  5. Verify file integrity and record the backup date, project, and operator.
  6. Test restoration in a separate staging project before considering production recovery.
Critical: Do not commit database dumps, customer data, .env files, API keys, payment secrets, Supabase service-role keys, or private credentials to GitHub. Do not run a restore against production without a separately confirmed recovery plan.

What is needed for automation?

A secure server-side backup job, private object storage, encryption and retention policy, audit records, and a restore test procedure must be configured before enabling automatic backup/restore controls. This UI remains read-only until those components exist.
